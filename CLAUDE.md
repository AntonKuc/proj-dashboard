# Инструкции для Claude в этом проекте

Дашборд консолидированной отчётности по проектам. Подробности — в
README.md. Здесь — правила работы конкретно с этим репозиторием.

## Перед изменением кода

Сначала объясни, как понял задачу, и жди явного "да" перед тем как
менять код. Не угадывай — если чего-то не хватает в задаче, спрашивай.

## Технические конвенции (обязательны для новых эндпоинтов/страниц)

- Все серверные ссылки — `/api/v1/...`.
- Единый формат ошибки: `{ "error": { "code", "message" } }` — см.
  `src/lib/api.ts` (`apiOk`, `apiError`).
- Списки — курсорная пагинация, не больше 200 записей за раз —
  `clampLimit` в `src/lib/api.ts`.
- Health-check у каждого сервиса — см. `/api/v1/health`.
- Ошибки в проде — через Sentry (см. `sentry.*.config.ts`), включается
  только если задан `SENTRY_DSN`.
- Проверка входных данных пользователя — через `zod` перед записью в БД.
- Доступ к другим доменам — не настраивается "пускать всех": CORS не
  открыт по умолчанию, добавляй только явный список при необходимости.
- Защищённые страницы проверяют сессию на каждый запрос — см.
  `src/middleware.ts` (страницы) и `src/lib/apiAuth.ts` (API).

## База данных

- Изменения схемы — только через Prisma-миграции
  (`npm run db:migrate:dev` локально, `db:migrate` в проде), никогда
  руками.
- Перед миграцией на проде — бэкап (Neon делает point-in-time restore,
  но перед крупными изменениями схемы лучше явно снять snapshot).
- Никогда не удалять колонки/данные без явного подтверждения, что они
  не нужны.

## Секреты

- Никогда не хардкодить ключи/пароли в код. Всё — через переменные
  окружения (`.env`, `.env.example` — список без значений).
- `data/raw_extract.json` и `.env*` — в `.gitignore` и `.claudeignore`.

## Git и деплой

- Мелкие правки — сразу в `main`.
- Крупные эксперименты — в отдельную ветку, в `main` — только после
  проверки.
- Перед любым деплоем — спросить: в `main` или в черновую ветку?
  Не решать самостоятельно.
- Перед деплоем проверить: нет отладочных `console.log`/тестовых
  надписей, нет захардкоженных ключей, тесты прошли (`npm test`),
  форматирование применено (`npm run format`).
- Не обновлять зависимости "на всякий случай" — только если нужна
  конкретная функция или есть угроза безопасности.

## Коннекторы (Такском, 1С, Google Диск, Яндекс Карты)

Сейчас в `src/lib/connectors/*` — заглушки, бросающие понятную ошибку
при отсутствии ключей. Перед тем как реализовывать реальный вызов:
получить один настоящий запрос/ответ от сервиса и свериться с ним —
не угадывать форму ответа. Детали — в `src/lib/connectors/README.md`.

## Код

- Комментарии и переменные — на английском (так принято в коде), текст
  интерфейса — на русском.
- Форматирование — Prettier, запускать перед коммитом (`npm run
format`).
